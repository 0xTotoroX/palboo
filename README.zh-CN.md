## 功能

把 Palboo 放在侧栏、页面浮层、桌面窗口或贴边／刘海面板。拖动排列工作台，选择哑光、磨砂或液态材质。入口菜单的强调点跟随当前位置；桌面窗口保留置顶，也可在调度中心显示并移到其他桌面。

桌面窗口使用 macOS 原生红黄绿按钮，沿用现有 Palboo.app 的 Dock 位置、应用身份和图标。红色收回聊天，黄色最小化并保留内容，绿色在当前桌面最大化，再点一次恢复原大小。放大后仍保留三个可用按钮与所选材质。

| 工具                  | 用途                                                                           |
| --------------------- | ------------------------------------------------------------------------------ |
| **下一步 · Stepwise** | 生成相关的后续建议，选择建议方向。                                             |
| **常用语**            | 独立管理常用提示词，选择填入、直接发送或单击填入／双击发送；可单独启停。       |
| **大纲**              | 沿用原文标题；无标题时补少量段落导航，点击定位原文。本地解析，不调用模型。         |
| **术语释义**          | 理解语境中的词义，收藏词条或标记已掌握。                                       |
| **任务看板**          | 管理待办、进行中和完成的任务，支持合并／完全展开视图、分组与拖动调整。                             |
| **模型切换**          | 切换 Codex 模型、推理强度和 Fast，保存预设并查看可用额度。                     |
| **提示词优化**        | 发送前改写草稿，也可以还原原文。                                               |
| **聊天测速**          | 按模型跨聊天保留最近测速，标明旧读数直到更新；可查看 Codex 提供的 token 用量。 |
| **Grok Bot**          | 查找已有 Bot，在当前聊天中发起咨询。                                           |
| **本地阅读与网站**    | 在 ChatGPT 内阅读／编辑本地笔记、预览表格，支持搜索、双链与图片，一键打开自定义网站。 |

## 安装

需要 **macOS 14+ 的 Apple Silicon Mac**，以及 **Codex / ChatGPT 桌面 App**。

1. 从 [GitHub Releases](https://github.com/0xTotoroX/palboo/releases) 下载 DMG。
2. 打开 DMG，把 **Palboo** 拖进「**应用程序**」。
3. 打开 Palboo。如果连接需要重开 Codex，会先询问。

DMG 包含完整 App，日常使用无需终端指令、Node.js 或 Rust。可选 Agent 和模型服务沿用你已有的安装与账号。

**手动更新：**在「**系统 → 启动与连接 → 应用更新**」点击「**检查更新**」，有新版后选择「**更新并重启**」。Palboo 校验并替换完整 App，保留设置；安装或启动失败会恢复旧 App，Codex 保持运行。检查和下载都由你主动触发，更新前先保存未完成的设置。开发模式可以检查，安装需要先切回正式模式。

**启动显示：**在「**系统 → 启动与连接 → 启动行为**」选择沿用上次状态、默认收起或默认打开；默认打开时可选聊天内工作台或桌面浮窗。下次启动 Palboo 时生效，已有配置继续沿用上次状态。左侧菜单移开后等待 3 秒再收回，移回即取消计时；内外两个方向都有切换动画，空间动画不可用时使用短缩放与淡入淡出，替代各功能里重复的进度文字。

已发布的 v1.2.0 及更早版本没有更新器，需要先手动安装一次包含此功能的版本。只有源码的补丁版显示更新说明，不提供安装按钮；位于只读位置的 App 需先移到可写的应用程序目录。

<summary>兼容性与首次打开帮助</summary>

- 桌面浮窗需要 macOS 15+；原生液态材质需要 macOS 26。不支持 Windows 和 Intel Mac。
- 如果 macOS 阻止打开，请确认安装包来自本仓库，再到「**系统设置 → 隐私与安全性 → 仍要打开**」中允许。不要关闭整个系统的安全防护。

- 以 `.0` 结尾的版本提供 DMG。补丁版本只有说明与源码归档；旧 DMG 不包含新补丁。

</details>

## 开始使用

1. **打开工作台**：单击 Codex 左栏的双眼入口，右键打开设置。
2. **选择工具**：在「**功能 → 功能开关**」中开关功能，对应功能页提供预览和相关设置；聊天测速位于「**功能 → 模型切换**」。在「**布局与位置**」中安排位置，在「**外观与字体**」中选择材质和语言。
3. **配置建议**：在「**系统 → 模型服务**」中使用 Codex CLI 登录或模型 API，测试连接后，在「**功能 → 下一步**」选择手动或自动生成。

默认点击建议只填入输入框。已有草稿时追加内容，不自动发送。

Bot「追问」续接本聊天中的上一次调用，保留已有草稿并把光标放到末尾，由你确认发送。

Grok Bot 的**最近消息**先显示摘要目录，点击摘要查看对应 Bot 最近一次完整回答，支持 Markdown；返回后恢复目录阅读位置。原 Bot 列表点击仍在主聊天填入咨询。阅读使用经账号核对的 Grok Bot 本机缓存，不消费未读回复；缓存缺失或不完整时，在 Grok Bot 打开对应 Bot 同步，附件仍在 Grok Bot 中查看。

侧栏、页面浮层和桌面窗口右上角「**…**」菜单都提供「**布局预设**」，桌面另外提供「**窗口置顶**」。所有设置入口都留在 ChatGPT 内置浏览器；「**管理布局预设…**」直达完整设置中的预设管理。可以保存和切换功能组合、分栏、标签顺序及比例，在「**布局与位置 → 布局预设**」中管理。切换保留草稿和阅读位置；预设使用主界面中已打开的功能，置顶和外观保持原值。

侧栏与桌面分别保存布局，切换位置保留草稿和阅读位置。贴边／刘海面板可以与主工作台并存，跟随 Codex 所在屏幕或固定在选定屏幕；悬停或按 `Command+Shift+M` 展开。可在「**布局与位置 → 启用范围**」分别启用新聊天和 Dots，默认关闭，适用于所有承载形式和功能；依赖回答内容的操作仍须等待回答。

Palboo 跟随 Codex 的外观。设置页统一使用「**跟随 ChatGPT**」，同步界面颜色、字体、字号、圆角、间距与控件样式。宿主提供双色配色时可直接同步浅色和深色，本机所选字形、悬停提示与滚动条也沿用该主题；设置页、桌面浮窗和贴边／刘海选用受支持的 OpenAI Sans/Serif 时，可直接读取本机 ChatGPT 包内字形，不安装、不联网下载或随 Palboo 分发字体。视觉以当前连接的 ChatGPT.app 为准，页头可选择自动／浅色／深色；导航、标题和分组控件跟随宿主，侧栏分类标题保留小强调色点，品牌与功能保持。原有主题和独立强调色入口已移除，旧配置仍兼容保留。「**外观与字体**」可分别设置设置页、聊天侧栏、页面浮层、桌面窗口、贴边／刘海的字体与字号。新配置默认跟随 ChatGPT，也可为每类窗口选择本机字体、75–150% 相对大小或 10–32px 固定字号；旧字体偏好继续保留，本机缺少所选字体时回退宿主字体。语言支持简体中文、英文和跟随系统，应用于全部 App 界面，不改个人内容；网站独立选择语言。展示页直接复用设置页的真实预览和隔离示例数据。左侧固定功能目录，右侧一次展示一个功能，滚动、点击或键盘均可切换九项功能；草稿、任务和收藏在切换后保留。小屏使用横向功能栏，保持正常字号与可操作控件。无需连接账户。保留原版品牌开场和双眼追视。首屏呈现完整显示器，滚动时支架收起并接近同一个实时屏幕，随后依次展示位置与材质；仍可手动操作，减少动态效果时使用自然排版。

<details>
<summary>Stepwise 方向与常用提示词</summary>

「**功能 → 下一步**」提供三种方向来源：

- **自动探索**：从当前问答中发现方向。
- **我来选择**：搜索十二个内置方向或自己的方向，拖动排序，也可使用 `Alt+上/下`。
- **智能挑选**：先让 Jev 判断候选方向，再由生成模型撰写建议。这是实验选项，需要独立凭据和同意。

新配置使用完整的最近一问一答，最多生成三条；没有合适建议时可以少给或不给。已有数量限制会保留。

方向库在「下一步」管理。内置方向的编辑与自定义方向只在本机生效，可恢复内置文案。点击可设为填入或发送，也可以把建议拖入关联输入框。

「**功能 → 常用语**」独立管理最多八条预设和点击模式。默认展示正文，短句直接阅读，长指令可展开全文；短名称选填，可开启「**仅显示名称**」切换为紧凑显示。也可直接在常用语面板添加、编辑和确认删除。关闭 Stepwise 后仍可使用；旧预设与原点击习惯保留。已有草稿始终保留并追加，不自动发送。

</details>

<details>
<summary>个人词库：新增、导入、导出与重置</summary>

在「**功能 → 术语释义**」开启聊天标注与释义。按当前聊天、收藏或已掌握浏览，可选点击术语跳转到上下文。

输入术语名称，或上传不超过 **8 MB** 的文件。下次主动发送主聊天消息时，由**该聊天当前的 Agent** 联网补全术语或解析文件。支持格式、联网和文件访问取决于 Agent，失败任务可以查看和重试。

导出只包含个人添加、收藏和已掌握的词条。重置删除个人添加、上传文件和待处理任务，保留基础词库及其中的收藏、掌握记录。没有来源记录的旧词条按基础词库保留。个人词库不会进入发布安装包。

</details>

<details>
<summary>模型、Bot 与连接</summary>

- **模型切换**控制 Codex 当前输入目标，与 Stepwise 使用的模型独立。模型、推理档位和额度来自 Codex，只显示可用能力。
- 「**系统 → 模型服务**」选择现有 Codex 登录时，模型列表与快切共用宿主提供的可选目录。读取列表不切换当前聊天模型；快切关闭后仍可读取。未连接或目录暂不可用时显示原因，可重新读取。
- **Grok Bot** 默认关闭。在「**功能 → Grok Bot → 接入 Grok Bot**」复制接入提示词给 Agent，BDK、MCP 和 Skill 仍独立安装。面板顶部可快捷打开 Grok Bot 应用，资料过期时仍可使用。咨询追加到输入框，不自动发送；关闭面板不会停止远端 Bot 任务。
- 「**功能 → 兼容集成**」的 Agent 菜单预览跟随 CodexHost 当前真实名单、可用状态、分组和选择，并提供状态、版本、更新和恢复操作。预览交互只改临时副本，可随时恢复当前配置。已启用并安装 CodexHost 时，Palboo 默认在启动时检查一次，有新版时提醒。可关闭启动检查或选择静默更新，新版在下次启动 CodexHost 时生效。外部宿主与 Agent 保留自己的配置。
- 「**系统 → 性能与开关**」可以暂停 Codex 连接，保留设置、任务和草稿。可选监测仅在该页可见时运行。

</details>

### 本地 Obsidian 与网站

在 **功能 → 功能开关** 启用 **网站**，文件夹与网站会显示在已有 Palboo 面板中。进入 **网站 → 本地笔记 → 添加文件夹**，选择已发现的 Obsidian 笔记库或任意本地 Markdown 文件夹，保存后即可打开。最多添加16个文件夹，可分别在 ChatGPT 内置浏览器打开多个页签，也可在阅读器侧栏切换。选择文件夹只填草稿，保存才授权；移除入口保留原文件。额外图片目录归各自文件夹管理。自定义 HTTP(S) 网站支持添加、编辑、删除和排序；无需单独的左栏图标、官方插件或公网部署。

阅读器支持标题／路径／全文搜索、双链与显示别名、标题／段落跳转、反向链接、本地图片和 Markdown 表格／代码。同名链接列出候选。目录使用开合文件夹图标，下划线前缀的文件夹优先，数字按自然顺序排列。直接读取磁盘文件，Obsidian 关闭后也可使用；刷新或回到阅读器时读取已保存的变化。阅读时不修改文件。库名、刷新和直达配置的 **笔记文件夹设置** 位于可折叠侧栏。点击 **编辑笔记** 可编辑 Markdown 源码，停顿后自动保存原文件；保存核对文件版本，外部修改产生冲突时保留草稿，未保存修改会阻止文章切换并触发浏览器离页提示。`.obsidian` 保持不变；网站配置位于 Palboo 数据目录，正文索引仅在内存，阅读位置和侧栏开合只在阅读器会话保存；编辑草稿在保存前仅保留于内存。

阅读器在独立端口仅监听 `127.0.0.1`，使用独立凭证，同一目录授权下后台重启尽量复用地址；每个文件夹的凭证、索引与阅读位置独立；修改或移除某个授权目录仅使该目录的旧链接失效，其他阅读页继续使用。拒绝隐藏文件、符号链接和授权目录以外的文件。外部图片需手动点击加载，不执行原始 HTML、脚本或 Obsidian 插件；XLSX／XLS／XLSM／XLSB／ODS 和 UTF-8 CSV／TSV 支持工作表切换与分页预览，显示已保存的公式结果（未计算的XLSX公式显示文本），不执行公式／宏，也不编辑表格；不复刻Excel图表和完整样式。笔记嵌入显示为链接，暂不渲染 Dataview／Canvas。每篇笔记上限8 MB、图片及工作簿32 MB、索引正文总量128 MB；表格预览上限十万行、512列、200工作表，CSV及传统格式的密集范围限两百万单元格；未索引笔记会明确提示。打开和搜索不会调用模型或把正文附到聊天。

命令行支持 `palboo config get web-library`、`palboo config schema web-library` 和 `palboo config catalog vaults`。通过 `palboo config set web-library --json '{"folders":[{"id":"notes","name":"笔记","path":"/absolute/path/to/notes","attachments":[]}]}' --confirm` 保存完整文件夹列表；新增时保留已有条目。`palboo config open-website folder:notes` 打开指定文件夹。旧 `vault`/`attachments` 字段和 `open-website obsidian` 继续兼容首个目录。更换授权或移除网站须带 `--confirm`，不会往笔记库安装文件。

## 维护与开发

<details>
<summary>更新或卸载</summary>

日常更新使用「**系统 → 启动与连接 → 应用更新**」。手动替换或卸载 App 前，先停止 Palboo：

```sh
"/Applications/Palboo.app/Contents/MacOS/palboo" stop
```

手动更新时用新版替换**整个 App**；卸载时删除 `/Applications/Palboo.app`。数据保存在 `~/Library/Application Support/palboo/`，只有希望清空数据时才删除该目录。

源码安装使用 `~/.local/bin/palboo stop`，卸载时也删除该可执行文件。

从 CodexBuddy 或 Codex Companion 升级时，先用 `~/.local/bin/codex-buddy stop` 或 `~/.local/bin/codex-companion stop` 停止旧后台。Palboo 会迁移默认数据目录，不自动合并独立目录。

</details>

<details>
<summary>源码构建与参与开发</summary>

需要受支持的 Mac、**Node.js 22.16+**、**Rust 1.88+** 和 **Xcode Command Line Tools**。

```sh
git clone https://github.com/0xTotoroX/palboo.git
cd palboo
npm ci
npm run install:dev
```

`install:dev` 登记本机开发环境，必要时安装完整 Palboo.app。平时只打开 Palboo，在「系统 → 启动与连接 → 运行模式」切换正式版与开发版。正式配置与各源码的开发配置、任务和数据分别保留。

`npm run install:local` 将当前源码构建成完整 App，与 DMG 使用相同结构，并保留兼容 CLI；更新不清空数据。旧 Dev Dock 入口会统一到 Palboo，旧 Dev App 保留归档。

通过 Palboo 打开 Codex 后：

| 命令                                                            | 用途                                      |
| --------------------------------------------------------------- | ----------------------------------------- |
| `npm run dev`                                                   | 连接真实 Codex 开发。                     |
| `npm run install:dev`                                           | 登记开发环境并准备统一 Palboo.app。       |
| `npm run dev:settings`                                          | 打开开发设置并选择 worktree。             |
| `npm run dev:stop`                                              | 停止后台开发会话。                        |
| `npm run verify`                                                | 完整验证，自动准备必要构建产物。          |
| `npm run verify:web`                                            | 前端与合成浏览器检查。                    |
| `npm run build`                                                 | 构建发布程序与设置网页。                  |
| `npm run package`                                               | 为 X.Y.0 打包完整 App DMG，补丁版本跳过。 |
| `npm run dev:site` / `npm run build:site` / `npm run test:site` | 预览、构建或检查独立介绍网站。            |

<summary>Agent 配置 CLI</summary>

使用当前运行 App 包内的 CLI。打开 Palboo 后：

```sh
PALBOO_BIN="/Applications/Palboo.app/Contents/MacOS/palboo"
"$PALBOO_BIN" config --help
"$PALBOO_BIN" config schema
"$PALBOO_BIN" config get settings
"$PALBOO_BIN" config set appearance --json '{"settingsTheme":"codex"}' --dry-run
"$PALBOO_BIN" config set appearance --json '{"settingsTheme":"codex"}'
"$PALBOO_BIN" config set settings --file - < settings-patch.json
```

源码安装时，将 `PALBOO_BIN` 设为 `"$HOME/.local/bin/palboo"`。以下示例对应当前源码，已安装版本支持哪些命令，以 `config --help` 为准。

用 `config schema <scope>` 查询嵌套字段、可选值和示例，涵盖下一步、外观、布局、模型切换、任务、术语、CodexHost 和性能。`config catalog models|displays|bots` 查询可用目录；Codex 可切换的实际模型见 `config get model-control`。

```sh
"$PALBOO_BIN" config set terminology --json '{"action":"add-names","names":["检索增强生成"]}'
"$PALBOO_BIN" config import terminology --file terms.pdf
"$PALBOO_BIN" config export terminology --format markdown --output my-terms.md
```

名称和文件（最多 8 MB）在下次主聊天发送时交给当前 Agent 处理。导出仅包含个人添加、收藏和已掌握词条。`config set terminology --json '{"action":"reset-library"}' --confirm` 删除个人内容及导入任务，保留基础词库及其中的收藏、掌握记录。

「布局与位置」的主界面布局中直接显示当前预设和管理入口。预设共用一个目录，标记为通用、侧栏推荐、浮层推荐或桌面推荐，仍可跨形式使用；各形式分别记住布局。CLI 的 `scope` 接受 `all`、`sidebar`、`overlay`、`desktop`，`main-preset-update` 可单独更新名称或标记而不覆盖已存布局。

布局预设也可由 Agent 操作：`config get layout` 读取预设及当前布局，`config schema layout` 提供 `main-preset-save`、`main-preset-apply`、`main-preset-update`、`main-preset-rename`、`main-preset-delete` 的字段和示例，通过 `config set layout --json` 执行。覆盖与删除需 `--confirm`，沿用界面的修订和布局校验。

用 `--data-dir` 指向其他安装。CLI 不会启动或重启 Codex。未提供的字段和凭据保持不变，数组、字典和布局树整体替换；读取时隐藏秘密，凭据通过文件或标准输入提供。

`--dry-run` 检查客户端字段与修订号，后台在保存时完整校验。破坏性或授权操作需要 `--confirm`，冲突不自动重试。
